# ts06-go-chi-react

Reference project for [gherkin-ai](https://github.com/FennerEduardo/gherkin-ai-cli) 3.2.1. An idempotent saga in Go with the chi router, and a React 19 frontend.

Everything in `generated-specs/` was generated by `ghk generate` from the specification in `features/go_chi_saga.feature`. The project builds, and its generated tests and runtime integration suite pass, as verified on 2026-10-25 (see [Verification](#verification)).

## Stack

| Part | Technology |
|---|---|
| Backend | Go 1.26 (chi) |
| Frontend | React 19 (Redux Toolkit, Vite) |
| Runtime kernel | PostgreSQL command service with idempotency and transactional outbox, outbox relay and inbox consumer with dead-letter queue over RabbitMQ (default), Google Cloud Pub/Sub or Azure Service Bus, saga orchestrator, OpenTelemetry trace propagation |
| Application layer | `POST /api/v1/<feature>/{id}/{command}` on the runtime command service; the tenant comes only from the validated JWT (`tenant_id` claim) |
| Architecture (configuration) | `monolith` |

> The configuration names `mysql` as the database, which shapes the generated schema. The runtime kernel and its integration suite use PostgreSQL, the database gherkin-ai verifies the runtime against.

## Build and test

The commands below are the ones gherkin-ai uses to verify this stack. Run them in `generated-specs` with the toolchain installed, or inside the official image `golang:1.26`.

```bash
cd generated-specs
go mod tidy
go vet ./...
go vet -tags integration ./internal/runtime/...
go build ./...
go test ./...
```

Runtime integration suite (IT1–IT7: transactional outbox, idempotency under concurrency, exactly-once relay, tenant isolation, saga compensation, inbox deduplication and dead-lettering, trace propagation), plus an HTTP test of the generated API (tenant from the JWT, idempotency key, outbox):

```bash
docker run -d --name ghk-pg -e POSTGRES_PASSWORD=ghk -p 5432:5432 postgres:17-alpine
docker run -d --name ghk-mq -e RABBITMQ_DEFAULT_USER=ghk -e RABBITMQ_DEFAULT_PASS=ghk -p 5672:5672 rabbitmq:4-alpine
export DATABASE_URL=postgres://postgres:ghk@localhost:5432/postgres AMQP_URL=amqp://ghk:ghk@localhost:5672
go test -tags integration -count=1 -v ./internal/runtime/...
```

The same suite runs against the Google Cloud Pub/Sub emulator. The gherkin-ai golden `go-pubsub` verifies this runtime's Pub/Sub adapter, and `go-servicebus` its Service Bus adapter against the official emulator:

```bash
docker run -d --name ghk-pubsub -p 8085:8085 gcr.io/google.com/cloudsdktool/google-cloud-cli:emulators \
  gcloud beta emulators pubsub start --host-port=0.0.0.0:8085 --project=local-project
export GHK_BROKER=pubsub PUBSUB_EMULATOR_HOST=localhost:8085 PUBSUB_PROJECT_ID=local-project
go test -tags integration -count=1 -v ./internal/runtime/...
```

Frontend (`generated-specs/frontend`, image `node:24-bookworm`):

```bash
cd generated-specs/frontend
npm install --no-audit --no-fund --loglevel=error
npm run build
npm test
```

## Production image and cloud deployment

`generated-specs/` has a production `Dockerfile` (multi-stage, non-root user) and a `.dockerignore`. The image is configured only through environment variables, so the same image runs on AWS ECS Fargate, Google Cloud Run, Azure Container Apps or Kubernetes. It listens on port 8080, with one health probe, `/health`, for liveness and readiness.

```bash
cd generated-specs
docker build -t transactional-system-go-chi .
docker run --rm -p 8080:8080 \
  -e DATABASE_URL=postgres://postgres:ghk@host.docker.internal:5432/postgres \
  -e AMQP_URL=amqp://ghk:ghk@host.docker.internal:5672 \
  -e JWT_SECRET='change-me-to-a-secret-of-32-chars!' \
  transactional-system-go-chi
curl -f http://localhost:8080/health
```

The runtime kernel chooses its event broker when it starts: `GHK_BROKER` if set, otherwise the broker whose variables are present, otherwise `stack.messaging`.

| Cloud | Broker | Variables |
|---|---|---|
| AWS | Amazon MQ for RabbitMQ | `AMQP_URL` (the broker's `amqps://` endpoint) |
| GCP | Pub/Sub | `GHK_BROKER=pubsub`, `PUBSUB_PROJECT_ID`; the token comes from the workload identity |
| Azure | Service Bus | `GHK_BROKER=servicebus`, `SERVICEBUS_NAMESPACE` (managed identity). The adapter is generated only with `stack.messaging: "servicebus"` |

The full list of variables and the per-cloud services are in the [deployment guide](https://github.com/FennerEduardo/gherkin-ai-cli/blob/main/docs/DEPLOYMENT.md).
